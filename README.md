# dev-pipeline для Codex

Тот же пайплайн разработки, что в плагине для Claude Code: требования → проектирование → план → код с ревью →
проверки → релиз → эксплуатация → CI. Скиллы, правила, документы и этапы одинаковые. Отличаются только
инструменты агента. Как термины Claude Code читаются в Codex, описано в
`dev-pipeline/skills/executor-catalog/references/codex-runtime.md`.

Сборка экспериментальная: в Codex её ещё никто не прогонял.

## Установка

1. Подключите маркетплейс и обновите его:

   ```bash
   codex plugin marketplace add Idontlikedrinkpivo/web-dev-pipeline-codex-plugin
   ```

   ```bash
   codex plugin marketplace upgrade
   ```

2. Установите плагин `dev-pipeline` из маркетплейса и перезапустите Codex.

3. Поставьте агентов-исполнителей. Плагин Codex не умеет приносить их сам, поэтому их ставит скрипт из папки
   плагина:

   ```bash
   bash ~/.codex/plugins/cache/dev-pipeline-codex/dev-pipeline/*/install-agents.sh
   ```

   Скрипт делает две вещи:
   - кладёт 31 агента в `~/.codex/agents/`;
   - разрешает вложенный вызов агентов (`[agents] max_depth = 2` в `~/.codex/config.toml`).

   Если путь к кэшу у вас другой, запустите `install-agents.sh` из папки установленного плагина.

4. Хук старта сессии напоминает правила пайплайна после сжатия контекста. Codex попросит разрешить его
   через `/hooks`. Если хук плагина у вас не срабатывает, поставьте его в личный конфиг:

   ```bash
   bash <папка плагина>/install-agents.sh --hook
   ```

## Модели

Агенты в оригинале закреплены за моделями Claude. Для Codex они сопоставлены в `models.json`:

| Claude | Codex |
|---|---|
| `opus` xhigh | `gpt-5.5` xhigh |
| `opus` high | `gpt-5.5` high |
| `sonnet` | `gpt-5.5` medium (low — там, где был low) |
| `haiku` | `gpt-5.4-mini` low |

На Codex это сопоставление не мерилось. Если модель недоступна на вашем аккаунте, запишите это в отчёт —
сопоставление поправим в сборке.

## Что проверить при первом прогоне

Начните с короткого пути на учебном проекте: `srs-writer` → `db-schema-design` → `openapi-spec-generator`.
Запишите, что вышло:

1. **Агенты.** Вызвал ли Codex агента-исполнителя по имени (`design-hard`, `doc-typist`), или сделал работу сам.
2. **Вложенность.** Смог ли писатель вызвать `doc-typist`.
3. **Модели.** Взялись ли модели из файла агента.
4. **Хук.** Сработал ли хук старта сессии.
5. **MCP.** Подключились ли Figma и context7 из `mcp.json`.

Что не сработало, присылайте с текстом ошибки или куском диалога.

## Чего нет в этой сборке

- `reflect` — разбор сессий для улучшения плагина. Он читает журналы Claude Code.
- Изоляция параллельных задач `work` в отдельных копиях репозитория. Сессия создаёт их сама через
  `git worktree add`.
- Строгий запрет записи для агентов-ревьюеров. В Codex он остаётся правилом в инструкции агента,
  а не ограничением инструментов.

Этот репозиторий собирается скриптом из репозитория плагина для Claude Code ([web-dev-pipeline-claude-plugin](https://github.com/Idontlikedrinkpivo/web-dev-pipeline-claude-plugin)). Руками его не правят: исправления вносятся в плагин для Claude Code, и сборка повторяется.
