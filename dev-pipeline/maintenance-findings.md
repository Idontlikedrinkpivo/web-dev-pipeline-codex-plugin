# Исправления плагина

## 1.3.5 — браузерная совместимость и правила интерфейса

Сверка Modern Web Guidance с Codex-версией показала: браузерный NFR не попадал в требования и тестовую матрицу,
семантика дат описывалась по частям, а проверка фокуса принимала тень за достаточную замену контура.
Добавлены локальные справочники browser-support и date-time-contract с маршрутизацией через SRS, БД, API,
архитектуру, ТЗ экрана, исполнителя и ревью. Браузерная матрица доходит до scaffold, E2E и CI;
итог кейса учитывает все требуемые браузеры, непроверенный браузер не считается пройденным.
Уточнены autocomplete/aria-invalid, forced-colors, выбор нативного решения перед новой зависимостью и
поиск по свёрнутому читаемому содержимому только по ТЗ. Существующие UI-компоненты сохраняют приоритет.
Сканер больше не отбрасывает снятый outline из-за соседней тени/focus-visible; находки остаются кандидатами,
внешний корректный fallback проверяется при чтении кода и в браузере. Источники указаны в THIRD_PARTY_NOTICES
и web-design-guidelines/references/modern-web-sources.md; внешний плагин и его CLI не подключены.

Проверки: 7 новых регрессий сканера; полный `python3.12 -m unittest discover -s tests -v` — 325 тестов,
118.671 с, OK (повтор перед выпуском). `check_plugin.py` — 0 замечаний; quick_validate — 16/16 затронутых скиллов; `git diff --check` — чисто.
Живой прогон исполнителя и приложения по новым инструкциям не запускался: сценарии для него перечислены
в `tests/behavior_cases/web-platform-policy.md` со статусом NOT_RUN. Места правил и границы проверки
перечислены в `acceptance-1.3.5.md`. Самостоятельный выпуск Codex, без переноса в Claude-версию.

## 1.3.4 — качество числовых правил, тестов и экранов

По разбору пользователя итерации «Дашборд руководителя» 1.2.0 Low-задачи неверно реализовали округление SRS,
а тесты не ловили важные дефекты; статический просмотр экрана пропустил потерю фона закреплённых ячеек при прокрутке на 1366.
Числовое правило теперь оценивается не ниже Mid. Пакет исполнителя требует BREAK CHECK с фактическим падением
на поломку каждого правила и восстановлением кода; пустое доказательство возвращает задачу, ревью оценивает его как P1.
SCREEN CHECK перечисляет размеры, действия, результат и снимки. Проверка каждого размера включает длинные
данные, высокие строки, прокрутку таблицы и открытие меню/диалогов у краёв.

Проверки: 3 новые регрессии совместимости `report_alarm.py`; полный unittest — 318 тестов, 165.261 с, OK;
проверка плагина — 0 замечаний, `ux-patterns/SKILL.md` — 498 строк, `work/SKILL.md` — 443.
Живой прогон исполнителя и браузера по новым инструкциям не запускался; это выпуск правил, не исправление приложения.
Места правил и их повторения перечислены в `acceptance-1.3.4.md`. Выпуск самостоятельный; без Claude и без push.

## 1.3.3 — принятие задач по сложности

Reflect показывал только общее принятие, поэтому нельзя было увидеть, задачи какой сложности чаще возвращались.
В `reflect/scripts/measure.py` добавлены сложность по колонке исполнителя, исход по колонке ревью,
таблица first/fixed/redone, подсказка для групп из ≥3 задач с принятием <50% и JSON `by_grade`.
Развёрнутая копия `.acceptance/<проект>/<версия>.txt` сохраняет прежнюю первую строку и читает старые файлы;
после удаления прогресса таблица восстанавливается из копии. Аннотация эскалации исполнителя сохраняет High
и сама не подменяет исход ревью. Формат файла прогресса не менялся.

Проверено: 8 новых регрессий; весь набор — 315 тестов, 125.340 с, OK;
`python3.12 dev-pipeline/check_plugin.py` — 0 замечаний; `git diff --check` — чисто.
Самостоятельный выпуск Codex 1.3.3; версия Claude не менялась. Отправку выполняет пользователь.
