## Требования дополнения

### R01. Ограничение объёма действует при следующем dispatch

Reflect, часть 1, находка 1: после требования завершить работу потребовалось повторно исключать необязательное health-2 упрощение. Правила уже есть в `work/SKILL.md` → Step 1 и `pipeline/references/convergence.md` → Scope shrinks / Only what blocks circles. Не создавать ещё один общий запрет и не расширять продуктовый scope.

Закрепить существующие правила сценарием исполнения/продолжения: задан конечный перечень обязательных проверок и доказанных регрессий; пользователь исключает необязательное улучшение; после checkpoint/compaction следующий пакет содержит только оставшийся согласованный объём. Необязательная идея остаётся в отчёте, не создаёт новый круг. Обнаруженная новая регрессия в изменённом коде с доказанным блокирующим исходом учитывается по действующему convergence; обязательные проверки молча не удаляются. Статический тест указателей правил не доказывает поведение агента — нужен отдельный B-case.

### R02. Отмена действия обновляет активные инструкции продолжения

Reflect, часть 1, находка 2: после явной отмены мутаций в resume и ограниченном плане закрытия оставались narrowmutants. Подтверждены устаревшие инструкции и ручная синхронизация, но фактический запуск после отмены не доказан.

Проверить действие уже существующего правила `work` → A decision that changes during the run: до следующего dispatch отмена отражена во всех актуальных инструкциях данного прогона — состоянии/checkpoint, resume, оставшихся gates и ещё не отправленном пакете. Исторические отчёты не переписывать, чужие прогоны не затрагивать. Статус `SKIPPED BY USER` с причиной; отмена не равна PASS и не выдается за исчерпание бюджета. После продолжения отменённая мутация не запускается повторно. Явная инструкция пользователя имеет приоритет над обычным требованием сохранять mandatory mutation ranges; остальные проверки продолжаются. Не спрашивать повторного подтверждения уже полученной отмены. Дополнить существующие задачи workflow и mutation budget, без новой подсистемы отмены.

### R03. Штамп закрытия проверяется по последнему действительному stamp

Reflect, часть 2, находка 3: корректное закрытие без новой строки changelog сохраняло версию документа, `doc_state.py dirty` возвращал 0, а `close_iteration.py` блокировал шаг «1 штамп». Источник всё ещё использует `where_am_i.unstamped()`; его ветка `doc.meta.version != iteration` не учитывает последующее корректное закрытие так, как `doc_state.last_stamp()`.

Проверенный локальный патч делегирует только шаг «1 штамп» существующей команде `doc_state.py <root> dirty`, запущенной тем же Python. Код 0 означает чистый stamp; ненулевой код или невозможность запустить проверку — блокировка с диагностикой, а не пропуск gate. Человекочитаемые имена документов нужны для сообщения, не для решения об успехе. Остальные шаги закрытия сохраняются; никакого force или повышения версии ради зелёного результата.

Патч применён только к установленной Codex-копии 1.2.266, не к этому исходному репозиторию. Требуется запланировать его включение в исходник и постоянные регрессии; не повторять изменение установленной копии и не синхронизировать Claude. Локальные доказательства: `/private/tmp/ai222-close-stamp-fix.patch`, `/private/tmp/ai222-close-stamp-repro-result.json`, `/private/tmp/ai222-close-stamp-applied.json`. Эти временные файлы — свидетельства, не обязательные входы будущего исполнителя: ожидаемые исходы полностью записаны здесь.

Четыре обязательных воспроизводимых сценария на временных Git-репозиториях:

1. Pins изменены, закрытия/штампа ещё нет → шаг штампа блокируется.
2. Корректный no-row close после изменения pins сохраняет прежнюю version → шаг штампа проходит.
3. После штампа есть незакоммиченная правка тела → блокируется.
4. После штампа закоммичено новое принятое решение → блокируется до следующего корректного stamp.

Дополнительно проверить отказ запуска/ненулевой код `doc_state` без распознанных строк: gate остаётся закрытым и показывает причину. Успех шага штампа не означает успех прочих шагов или разрешение создавать тег. Исходник изменения — `dev-pipeline/skills/pipeline/scripts/close_iteration.py`; контракт — `dev-pipeline/skills/doc-versioning/scripts/doc_state.py` (`last_stamp`, `dirty`). Использовать существующую задачу, уже меняющую close gate, если это сохраняет её связность; не дробить небольшой определённый патч на отдельные дорогие dispatch.
